# ADR-0001: 按 C5 口径拆除 bank_txn_leg / composite-steps 下钻，终态收口收敛到 order 级

- 状态：Accepted（2026-07-14 用户拍板「彻底修正 · 移除旧代码」）
- 上位口径：2026-06-23 用户决策 C5（lending-recon `docs/design/20260623-对接gateway-bank_txn_leg跨库方案.md` §C5）：
  **「wedap 组合交易(leg/step)对 recon/lending 透明，对账只在 order 业务级(biz_seq_no)，绝不下钻 leg」**
- 取代：`docs/20260617-sync-terminal-order-finalize-design.md` 中所有 leg 相关设计（§3.4 明细补拉、
  worker 候选②「终态但 legs 缺失」、apply_legs 聚合收口）；order 级部分（CAS/finalize/G2/G6）继续有效

## 背景

wedap 包装组合交易并返回组合交易结果；拆分细节（leg/step）是 wedap 内部实现。C5 拍板后
recon 侧已按 order 级实现（GatewayOrderCollector 只读 `bank_txn_order`/`order_stuck_alert`），
但 gateway 自身的 legs.py / order_reconcile_worker（20260617 finalize 设计）没跟上口径，仍在拉
`/composite-transactions/{biz}/steps` 落 `bank_txn_leg` 并用 leg 聚合收口父单终态。

2026-07-14 DEV 联调实锤该遗留的代价：wedap steps 响应无 `txnDate` → `apply_legs` 整单拒绝 →
dev-hw `bank_txn_leg` 零落盘、order_reconcile worker 每分钟空转重试、回调 after_ingest 同因失败。
若按「wedap 补 txnDate」修，等于把违背 C5 的依赖固化成跨团队契约——方向性错误。

## 决策

**gateway 不感知组合交易拆分细节**。父单终态收口全部走 order 级信号：

| 路径 | 收口信号 | 实现 |
|---|---|---|
| 同步 | 提交响应 `txnStatus`（map_wedap_txn_status） | `submit.py`（不变） |
| 回调 | 回调 body `txnStatus`；缺失时回落 status-query | `callback_finalize.resolve_callback_terminal`（新） |
| 兜底 | wedap status-query（order 级） | `order_status_reconcile`（升为唯一兜底路径） |

三路径共用 `finalize_terminal_in_session`（finalized_at/via + audit + 转发 lifecycle，
稳定 dedup_key `fwd-{tenant}-{biz}-{status}`）不变。

### 移除清单（本 ADR 落地 commit）

- `app/services/legs.py` 整文件（apply_legs_in_session / sync_legs_for / LegsSyncIncomplete）
- `app/models/txn.py::BankTxnLeg` + alembic `0019_drop_bank_txn_leg`（删表；downgrade 重建空表）
- `app/clients/wedap.py::get_composite_steps`
- `app/domain/states.py::LegStatus / aggregate_order_status`
- worker 候选②「终态但无 leg」扫描与 leg 兜底回落；`GW_ORDER_RECONCILE_LEG_BACKFILL_SECONDS` 配置
- 相关测试（test_legs.py 等）同步删除/改写；新增 `test_callback_finalize.py`

### 回调收口语义（替代 leg 聚合）

- body `txnStatus` ∈ {SUCCESS, FAILED} → FOR UPDATE + CAS + finalize（source=CALLBACK）
- body 无终态（非终态通知/字段缺失）→ 回落 status-query；仍未收敛 →
  `CallbackTerminalUnresolved` → inbox 留 RECEIVED 等 wedap 重试/重放驱动
- 已终态但回调结论不一致 → **只告警不倒退**（终态防倒退），视为已处理
- 乱序回调（order 未建）→ 留 RECEIVED 待重放

## 影响与不做

- **跨仓无阻断**（2026-07-14 全仓核实）：recon 只读 order/stuck_alert；lifecycle 收 order 级
  `terminal_event`；admin 前端无 leg 展示。
- **COLL（归集）**：wedap 无 status-query → 只能靠回调收口；回调丢失超 max_age 由 G6
  `order_stuck_alert` 显式告警交人工。此前 leg 路径对 COLL 同样兜不到（wedap 404 无执行记录），
  无能力回退。
- **冲正（REVERSED/PARTIALLY_REVERSED）**：OrderStatus 枚举与状态机出边保留；leg 金额覆盖度
  判定已删。未来冲正终态由 wedap 回调/状态查询的 order 级字段驱动（wedap reversal 契约落地后接入）。
- **银行侧明细对账**不依赖本仓：走 wedap 两方对账文件（recon L1）与 `deposit/transactions` 查询。

## 验证

- 单测 633 passed，行+分支覆盖 100%（fail_under=100 门禁）
- local / dev-hw 部署后：`bank_txn_leg` 表删除、order_reconcile 不再出现 LegsSyncIncomplete 空转、
  回调收口 dev 联调复验（见 lending-workspace `01-investigations/20260714-lending-wedap-dev联调报告/`）
